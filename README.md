# 仓库管理系统

面向多人协作的中文仓库控制台，采用 **Cloudflare Pages + Workers + D1**。库存、单据、流水、员工、商品、仓库和审计日志全部通过 Worker API 保存到云端 D1，前端不使用 localStorage 作为业务数据源。

## 当前能力

- 工作台：实时库存总量、待审核单据、低库存预警、近 30 天真实出入库趋势、库存与流水净额核对
- 库存总览：真实库存、仓库筛选、SKU/分类搜索、库位和安全库存
- 入库、出库、盘点、调拨：单据提交、现场操作人、审核、驳回原因、库存流水
- 扫码：USB/蓝牙扫码枪键盘输入、手机摄像头扫码、SKU/条码手动输入
- 报表：按月查询并导出真实出入库流水 CSV
- 权限：管理员、仓库主管、操作员、查看人员；登录页关闭自助注册，员工账号只能由管理员创建
- 删除与历史保护：管理员可删除未审核/已驳回单据；已审核单据不可删除；有历史引用的商品只能停用，不破坏历史账目
- 审计：提交、审核、驳回、删除、商品停用、员工和仓库权限变更写入审计日志
- 账务保护：审核写入使用 D1 batch 事务；出库审核检查库存；库存触发器阻止负库存；单据编号含随机熵，降低并发重复编号风险

## 云端数据库

`wrangler.toml` 已绑定 D1 数据库 `wmsystem-db`。标准迁移文件位于 `migrations/`，不要只执行根目录历史 SQL。全新数据库按编号顺序执行 `0001` 到 `0008`；已有数据库升级时先检查已执行迁移，避免重复执行包含 `ALTER TABLE` 的文件。

`0006_inventory_opening_integrity.sql` 增加库存期初基准，用于核对：

```text
账面库存 = 期初库存 + 已审核流水净额
```

发现差异时，管理员或仓库主管可在工作台看到异常数量，并应先处理异常再继续大批量业务。

## Cloudflare 发布

请阅读 [CLOUDFLARE_DEPLOY.md](./CLOUDFLARE_DEPLOY.md)。发布前必须完成 D1 迁移、配置 `SESSION_SECRET`，并使用统一的 `pnpm run build:pages` 生成包含最新 `_worker.js` 的 `client/dist`。新库还需通过一次性 `BOOTSTRAP_TOKEN` 完成首个管理员初始化。不要把密码、API Token 或 Secret 写入源码。

## 操作规则

1. 只有管理员可以创建、停用员工账号和修改仓库名称。
2. 入库、出库、调拨、盘点都必须填写现场操作人，且不能填写当前登录账号姓名。
3. 待审核或已驳回单据可由管理员受控删除，删除只改变单据状态并保留审计记录。
4. 已审核单据、库存流水和审计日志不可直接删除；如果发生业务冲销，应通过反向业务单据处理，不能抹掉原始账目。
5. 有历史流水、单据明细或库存引用的商品不会物理删除，只会停用。

## 首个管理员初始化

新建空 D1 后配置一次性 `BOOTSTRAP_TOKEN`，调用 `POST /api/auth/bootstrap` 并携带 `X-Bootstrap-Token` 创建首个管理员。该接口只有在 users 表为空时可用；成功后立即删除或轮换该 Secret，之后员工只能由管理员在系统内创建。
